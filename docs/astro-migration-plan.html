3. Migration plan

Phase 0 — Baseline

  • git tag codekit-legacy (or branch) to preserve current working state.
  • Fix live bugs (#1–#4 at minimum) before or during migration.

Phase 1 — Scaffold

  • New Astro project in astro/ subfolder (or new repo).
  • Config: output: 'static', site: 'https://www.iam314.com', trailingSlash: 'always'.
  • Copy static assets into public/: css/, fonts/, images/, uploads/, js/lyudmils.js, PDF, CNAME, robots.txt, google4ca3a6165e588755.html, zohoverify/.

Key decision — images: keep hand-optimized AVIFs + -p-* variants in public/ with existing <img>/srcset markup. Do not run them through Astro’s image pipeline initially (avoids re-encoding, zero visual regression). Can adopt astro:assets selectively later (e.g. uploads gallery).

Phase 2 — Component architecture (1:1 mapping)

CodeKit Astro
_header.kit + _header-case-study.kit + _header-product.kit src/layouts/BaseLayout.astro with schemaType prop (base / case-study / product)
<!-- $title --> $link $description $ogimage Layout frontmatter props
_nav.kit + <!-- $work = current --> src/components/Nav.astro — active state via Astro.url.pathname
_footer.kit / _footer-inner.kit / _footer-photoonly.kit src/components/Footer.astro with variant prop
_cta.kit, _faq.kit src/components/CTA.astro, src/components/Faq.astro
JSON-LD in headers src/components/Head.astro — Person/Org/WebSite/WebPage + optional Product/CreativeWork
Header scripts (gtag, Payhip, Swiper, Lottie) src/scripts/ + <script> / is:inline

Phase 3 — Pages

  • Static pages → plain .astro files (body HTML copies over nearly verbatim): src/pages/index.astro, contact.astro, newsletter.astro, thanks.astro, niceandrandom.astro
  • Work index → src/pages/work/index.astro
  • 12 case studies → fast path: individual .astro pages with shared CaseStudy layout (keeps hand-editing HTML as today). Nice-to-have: src/content/work/*.md(x) content collection with frontmatter (title, labels, og-image, up-next) so pages become data-driven.
  • Store → store/index.astro + src/pages/store/[slug].astro (5 products) with Product schema (price, availability, Payhip buttons).
  • “Up next” → src/components/UpNext.astro (repeated 12× today).

Phase 4 — Redirects & SEO

  • 8 legacy meta-refresh redirects → Astro redirects config (proper 301s).
  • @astrojs/sitemap → auto full sitemap (fixes bug #4 permanently).
  • src/pages/404.astro styled like the site.
  • Keep robots.txt, CNAME, verification files in public/.

Phase 5 — JS & theming

  • Clean lyudmils.js (strip dead code), move to src/scripts/, load from layout.
  • Optional: inline critical theme script in <head> to avoid light→dark flash (currently defer'd).

Phase 6 — Build, verify, deploy

  • npm run build → dist/; diff URLs against build/ / live site (links, trailing slashes, og images, schema).
  • Deployment (replaces manual build/ push to the pages repo):
  • Keep the existing pages repo as the target, but stop committing build output manually.
  • Add a GitHub Actions workflow in this repo that runs on push to main:
    1. Checkout this repo
    2. Set up Node (e.g. v22+, actions/setup-node)
    3. npm ci
    4. npm run build
    5. Deploy dist/ to the pages repo (e.g. peaceiris/actions-gh-pages with publish_dir: dist + the CNAME file kept in public/), or publish via actions/deploy-pages if GH Pages is configured on this repo instead.
  • Alternative if they prefer to keep a separate pages repo: use peaceiris/actions-gh-pages pointing at that repo (needs a token with repo scope).
  • Sketch of the workflow (see also docs/ for reference):
name: Build & Deploy
on:
  push:
    branches: [main]
permissions:
  contents: write
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v4
        with:
          personal_token: ${{ secrets.PAGES_TOKEN }}
          publish_dir: ./dist
          external_repository: <owner>/<pages-repo>
          publish_branch: main
